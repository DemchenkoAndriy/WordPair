# Публікація на GitHub Pages

## Що вже налаштовано

| Файл | Роль |
|---|---|
| `.github/workflows/deploy.yml` | Збірка + публікація на Pages при пуші в `main` (або вручну) |
| `.github/workflows/ci.yml` | Тести й збірка на всіх інших гілках і в PR |
| `vite.config.ts` | Базовий шлях із `PUBLIC_BASE_PATH`, SPA-fallback `404.html` |
| `scripts/generate-icons.mjs` | Іконки PWA 192/512 (`npm run icons`) |

## Одноразове налаштування (потрібен доступ власника репозиторію)

1. **Settings → Pages → Build and deployment → Source: `GitHub Actions`.**
   Це єдиний обов'язковий крок; без нього workflow впаде на кроці `deploy-pages`
   з помилкою про невключений Pages.
2. Злити гілку `claude/word-learning-app-architecture-vwti3x` у `main`
   (workflow слухає `main` і `master`; зараз у репозиторії ще немає жодної з них).

Після цього кожен пуш у `main` публікує сайт на:

```
https://demchenkoandriy.github.io/WordPair/
```

Запустити публікацію вручну: **Actions → Публікація на GitHub Pages → Run workflow**.

## Чому саме так

### Базовий шлях приходить із CI, а не зашитий у код

Pages віддає проєкт із підкаталогу `/<repo>/`, а не з кореня домену. Якщо зашити
`/WordPair/` у конфіг, форк або перейменування репозиторію мовчки зламають усі
шляхи до ассетів. Тому workflow передає:

```yaml
PUBLIC_BASE_PATH: /${{ github.event.repository.name }}/
```

Локальна збірка без цієї змінної йде з кореня — `npm run dev` і `npm run preview`
працюють як раніше.

Відтворити збірку в точності як у CI:

```bash
PUBLIC_BASE_PATH=/WordPair/ npm run build
PUBLIC_BASE_PATH=/WordPair/ npm run preview   # http://localhost:4173/WordPair/
```

### 404.html як SPA-fallback

Pages — статичний хостинг без rewrite-правил: будь-який шлях, крім наявного файлу,
дає 404. Плагін `wordpair:spa-fallback` копіює `index.html` у `404.html`, і Pages
віддає застосунок на будь-якому шляху.

Зараз навігація тримається в стані, а не в URL, тож це запобіжник на майбутнє —
коли з'являться посилання на конкретну колоду.

### Маніфест PWA — з відносними шляхами

`start_url: './?source=pwa'` і `scope: './'` розв'язуються відносно самого маніфеста,
тому встановлення на домашній екран працює і з кореня домену, і з підкаталогу Pages.
Іконки прописані так само відносно.

### Тести перед публікацією

`npm test` стоїть у workflow до збірки: 40 тестів домену виконуються за ~0.6 с,
і це дешева страховка від публікації зламаної логіки нарахування чи повторень.

## Оновлення в користувачів

`registerType: 'autoUpdate'` — service worker сам завантажує нову версію у фоні
й застосовує її при наступному відкритті. Окремої кнопки «оновити» не потрібно.

Наслідок під час розробки: після деплою свіжу версію видно **з другого відкриття**.
Щоб перевірити зміни одразу — DevTools → Application → Service Workers → Unregister.

## Обмеження

- Репозиторій має бути публічним, або потрібен GitHub Pro/Team — Pages для приватних
  репозиторіїв недоступні на безкоштовному тарифі.
- Прогрес зберігається в IndexedDB конкретного браузера. Синхронізації між пристроями
  немає — це свідоме рішення (див. `docs/ARCHITECTURE.md`, Р2).
